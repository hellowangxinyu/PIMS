## 1. 项目定位

**PIMS（Pengyuan Integrated Management System）是广东芃远新材料有限公司的企业综合管理系统**，覆盖原材料采购、生产配方、委外加工、仓储物流、质量检验、销售、财务应收应付、经营报表等**全业务域的一体化管理**。

> ⚠️ **定位说明**：PIMS 是**综合管理系统**，不是单纯的进销存系统。进销存（采购/销售/库存）只是其中的基础业务板块，配方管理、生产管理、委外管理、质检管理、成本核算才是体现行业特性的核心板块。

- **团队规模**: 5-10 人使用
- **部署**: 单文件 jar + SQLite 单文件数据库，适合小团队快速部署
- **开发原则**: 快速开发、简便部署。不加不必要的新依赖，复用现有模块和模式，代码写完即能用
- **业务特性**: 涂料公司。生产订单 = 配方表，委外订单 = 配方表
- **首要质量要求**: 库存增减计算的准确性（所有库存变动必须由单据驱动并可追溯）

## 2. 技术架构

| 层 | 选型 | 说明 |
|---|---|---|
| 前端 | Vue 3 + Element Plus + Vite | 单页应用，响应式（手机/平板/桌面） |
| 后端 | Spring Boot 3.3.2 + Spring Data JPA | RESTful API |
| 数据库 | SQLite (WAL 模式) | 单文件零维护 |
| 认证鉴权 | Sa-Token 1.38 | Token + 角色权限注入 |
| 并发控制 | WriteQueue 应用层写队列 | SQLite 写串行排队 |
| 部署 | java -jar 单文件 | 内嵌 Tomcat，端口 8080 |

### 关键技术约定

- `spring.jpa.hibernate.ddl-auto=none`：表结构由启动初始化器（`RecipeSchemaInitializer` 等）通过 `PRAGMA table_info` + `ALTER TABLE ADD COLUMN` **幂等补列**维护，禁止依赖 Hibernate 自动建表（SQLite 表多时元数据查询超限）
- 日期字段（LocalDate）在 SQLite 中以**毫秒时间戳**存储（UTC+8 零点）
- 权限码新增后必须在 `DataInitializer.syncRecipePermissions` 中同步到已有角色（**admin 用户角色为 SS**，务必包含 SS 行），否则启动后 403
- 前端构建产物直接输出到 `pims-server/src/main/resources/static`，随 jar 一体部署
- 构建流程：`npm run build`（前端）→ `mvn clean package -DskipTests`（后端）→ `java -jar target/pims-server-1.0.0.jar`

## 4. 功能模块详细说明

### 4.1 工作台（仪表盘）

- 统计卡片实时展示：仓库数量、物料数量、物料大类数、供应商数量、客户数量（后端 `/api/dashboard` 直接 count 查询）
- 图表区：业务趋势可视化（SVG 自绘组件 SvgLineChart / SvgBarChart / SvgDonutChart，零第三方依赖）

### 4.2 基础数据

#### 4.2.1 物料管理

- **字段精简**：编码、品名（全局统一称「品名」，不叫"名称/物料名称"）、牌号、大类、小类、质保期(天)
- **品牌归属（v4.5 新增）**：`brandOwner` 字段，仅对成品物料（大类C）有意义
  - 自产成品默认「芃远」
  - 外购成品：在物料弹窗中可从成品供应商下拉选择，选中后 `brandOwner` = 供应商名称
  - 成品采购保存时校验：供应商名称必须等于物料 `brandOwner`，不一致报错
- **大类/小类为字典项**（material_category / material_sub_category），可在数据字典维护
- **分类编码规则**（必须使用字典编码而非中文）：
  - 大类：A=助剂、P=颜料、F=填料、R=树脂、S=溶剂、**B=半成品**、**C=成品**
  - 半成品小类（色浆）：白浆BW(60)、红浆BR(61)、黄浆BY(62)、绿浆BG(63)、黑浆BB(64)、蓝浆BL(65)
  - 成品小类：底漆CD(70)、清漆CQ(71)、背漆CB(72)、面漆白色系CW(73)、红CR(74)、黄CY(75)、绿CG(76)、蓝CL(77)、黑CK(78)、其他色CO(79)
- **平替物料（v5.2，仅原材料，双向关系）**：原材料（大类 A/P/F/R/S）可在编辑弹窗配置「平替物料」（可多选，仅限其他原材料）——表示该物料可被这些物料完美替代；**平替为双向自动同步**：A 配置平替 B 后，B 的平替列表自动包含 A（新增反向加入、移除反向清除、去重幂等），配方树编辑时原料节点显示「⇄平替」按钮一键切换、可来回切换（用量保持不变，成本保存后重算）；后端校验平替仅限原材料、不能替代自身、物料必须存在
- 页面顶部按大类标签筛选，支持编码/品名模糊搜索
- **质保期**（shelfLifeDays，0/空表示不限）：过期日期 = 入库日期 + 质保期，库存页实时显示剩余天数，库龄着色（≤60天绿 / 61-90天橙 / >90天红）

#### 4.2.2 编码规则

- 物料编码格式：`小类代码 + 数字开头 + 3位序号`（如 AC40001、BW60001、CD70001）
- 按大类、小类分级管理，新增物料选小类后自动生成唯一编码，序号自动递增，**编码一旦生成不可修改**

#### 4.2.3 客户管理

- 字段：编码、名称、联系人、电话、地址、等级（A/B/C）、**收款条件（账期缓冲）**、**收款方式**、备注
- **收款条件**（与供应商共用字典 payment_terms）：款到发货 PREPAID / 账期30天 CREDIT_30 / 账期60天 CREDIT_60 / 月结 MONTHLY / 两月结 TWO_MONTH / 三月结 THREE_MONTH / 自定义账期（1-365天，存为"账期N天"）
- **收款方式**（字典 payment_method）：电汇 TRANSFER / 承兑 ACCEPTANCE（与客户谈判的结果）
- 客户账期决定应收账款的缓冲时间（见 4.9 应收应付）
- 查重：同名客户不允许重复录入

#### 4.2.4 供应商管理

- **分类**：MATERIAL（材料供应商）/ FINISHED（成品供应商）；原料采购仅关联材料供应商，成品采购仅关联成品供应商
- **字段精简**（v2.0）：编码、名称、类型、付款条件、付款方式（已删除联系人/电话）
- **付款条件/付款方式受权限码 `supplier:payment` 控制**，仅 GM 与 FINANCE 角色可见
- 付款条件/付款方式均为字典化选项，可在数据字典扩展

#### 4.2.5 仓库管理

- **三级结构**：仓库 → 分库（如树脂库、溶剂库、助剂库）→ 库位
- 分库编码自动生成 `Z+3位序号`（Z001…），库位编码 `L+3位序号`（L001…），**不可手改**，新增时仅填名称/排序/备注
- 「所属工厂」为手动输入字段，不从供应商信息获取
- 委外仓：仓库类型 OUT_RAW，关联代工厂（如邦弗特山东委外仓、昇润广东委外仓）

#### 4.2.6 数据字典 / 用户 / 角色

- 数据字典：物料大类/小类、付款条件、付款方式等均为字典项，支持增删改
- 用户角色：GM(总经理)、SS(管理员，admin 默认角色)、PM、TECH_LEAD、TECHNICIAN、OUTSOURCE、STOREKEEPER、BUYER、SALES、FINANCE、QC
- **权限层级化控制**（四维度）：① 模块可见性 ② 单据操作（read/write）③ 审核/反审核 ④ 字段可见性（如 supplier:payment、purchase:price、finance:amount）

### 4.3 配方管理

#### 4.3.1 配方类型

- **制浆（研磨 GRINDING）**：原材料研磨生成色浆（半成品，物料大类 B）
- **制漆（调色 TINTING）**：原材料 + 色浆调配生成成品油漆（物料大类 C）
- 前端以两个独立 Tab 页分类展示与管理

#### 4.3.2 多级 BOM 与版本控制

- 配方树支持 MATERIAL（原料）与 SUB_RECIPE（半品子配方）节点，多级嵌套
- 版本状态流：DRAFT → RELEASED → ARCHIVED，同一时间仅一个 RELEASED 版本
- **标准批量固定 100kg**；生产/委外订单的生产批量不得低于 100kg，否则禁止保存
- 保存配方树校验：根节点物料用量之和必须等于标准批量

#### 4.3.3 配方成本直出

- 配方列表、版本表、配方树均直出成本，无需额外操作
- **取价规则**：材料优先取库存台账加权平均价（Σ金额÷Σ数量），无库存回退最近采购价；半成品按子配方 RELEASED 版本成本递归计算（防循环引用）
- 提供 `GET /api/recipe/costs`（已发布配方成本）与 `GET /api/recipe/version/{id}/cost`

#### 4.3.4 配方打印（保密版）

- 选中配方后点击「打印」，浏览器原生 window.print() 新窗口渲染 A4 排版
- **保密规则（v5.1 调整）**：原料不显示物料名称（品名）、不显示单价/成本/成本汇总，**保留物料编码**（工人按编码找料）；**半成品显示名称并加粗，其子配方明细展开缩进展示**（层级清晰，最多缩进 3 级）
- 内容：标题（制浆/制漆配方单+时间）、基本信息表（编号/品名/产品编码/分类/版本/标准批量/描述）、保密明细表（序号/物料/类型/分类/用量/单位）、签批栏（制单人/审核人留白签字）

#### 4.3.5 配方禁用/启用（v4.3）

- **禁用入口**：配方管理页面右侧详情面板底部「禁用/启用」按钮（必须先在左侧列表选中配方，右面板才会出现操作按钮）
- **禁用规则**：禁用后该配方**不可被任何单据引用**——生产订单、委外订单创建时调用 `checkReferenceable(recipeId)` 校验，若 `enabled=false` 抛出「该配方已禁用，不可引用」
- **启用恢复**：可随时启用，启用后恢复引用能力
- **列表状态筛选**：配方列表顶部提供「启用中」「已禁用」两个状态 Tab，分别筛选 `enabled=true/false` 的配方；列表中状态列用绿色「启用」/ 灰色「停用」标签区分
- **API**：`PUT /api/recipe/{id}/enabled?enabled=true|false`
- **数据模型**：`recipe.enabled` 字段（Boolean，默认 true）

### 4.4 生产管理

#### 4.4.1 生产订单（即配方表）

- 创建时先选配方类型（制漆/制浆），下拉按类型分组展示已发布配方
- 选择配方后按生产批量**按比例自动计算投料量**：实际投料量 = 配方用量 ×（生产批量 ÷ 配方标准批量）；支持任意批量输入
- 状态流：DRAFT → CONFIRMED → COMPLETED
- **列表 Tab 分组（v4.3）**：列表顶部按状态拆分为两个 Tab，每个 Tab 显示对应数量徽标（实时刷新）：
  - **未完工**（默认）：`status IN (DRAFT, CONFIRMED)`
  - **已完工**：`status = COMPLETED`
- 溯源：订单可追溯完整配方谱系树 + 实际领料批次（见 4.4.4）
- **生产订单打印（v5.25）**：「生产订单·投料单」——操作列「打印」（仅已确认/已完工），A4 打印：订单头（单号/产品/配方编号/批量/状态/制单人）+ 投料明细（品名+编码+规格+用量，半成品行标「半成品」）+ 投料人/车间主管签字栏；无价格列（成本保密）；`GET /production-order/{id}` 取数

#### 4.4.2 生产出库（领料）

- 必须参照已确认的生产订单，按配方明细批量生成出库单
- **参照订单过滤（v4.6）**：参照下拉仅显示可出库的生产订单，已完工订单（COMPLETED 状态、已存在 DONE 入库单、或已存在 CONFIRMED 出库单）直接不显示，避免选中后才报错。接口 `GET /api/outbound/referenceable-production-orders?forType=outbound`
- **批号强制必选**（前后端双重校验，后端返回 400「物料 xxx 出库必须选择批号」）
- 批次下拉显示：**批号 + 分库/库位 + (现存量:x)**，**不显示价格**（同批号多库位自动聚合）
- **出库用量可直接编辑**（最小 0.001，精度 3 位）
- 参照订单领料**自动确认**并立即扣减库存（历史草稿保留手动确认按钮）
- 出库单持久化 **unit_price（按批号直取库存台账单价）与 cost = qty × unitPrice**（实际成本）
- **生产退料（v5.54）**：领料差异处理通道——生产领料页「退料」按订单弹窗，带出已领明细（已领/已退/可退量），逐行勾选填退料数量（上限=可退量）；单据为 `production_outbound` 表 `doc_type=RETURN` 的**负数行**（qty/cost 为负、status=CONFIRMED、单号 PROD-RET-YYYY-NNNN、单价按原领料行直取），库存按原批次原库位加回（不重置批次质保期），成本核算 SUM(cost) 口径自动净额
- **补领（v5.54）**：领料弹窗切「补领」模式后，已领料订单也可再次参照（仍排除已完成入库的订单）；各行默认用量 0，仅填写本次追加的用量，防止按配方全额重复领料

#### 4.4.3 生产入库

- **前置校验（v4.3）**：必须先完成生产出库（领料）。参照生产订单生成生产入库单时，系统校验存在已确认的生产出库单，否则抛出「该生产订单尚未进行生产出库，不允许参照生成生产入库单」。生产订单完整流程：①创建 → 确认 → ②生产出库（领料）→ 确认 → ③生产入库（前置校验通过）→ 来料质检 → 入库
- **参照订单过滤（v4.6）**：参照下拉仅显示可入库的生产订单（必须已出库且无 DONE/CONFIRMED 入库单），已完工订单直接不显示。接口 `GET /api/outbound/referenceable-production-orders?forType=inbound`
- 必须参照生产订单；需完成仓库→分库→库位三级选择
- 确认后创建来料质检单（refDocType=PRODUCTION_INBOUND，待检状态），QC 合格后正式入库（PRODUCTION_IN 异动）
- **入库时强制自动生成批号**：`B + 日期(YYYYMMDD) + '-' + 当日3位序号`（如 B20260801-001），不支持手动传入；同时记录 inboundDate=当天，expiryDate=inboundDate+shelfLifeDays
- **得率记录**：单据持久化 theoreticalQty（理论产出=订单配方批量）与 yieldRate（得率%=实际产出÷理论产出×100）；页面直出「实际产出/理论产出/得率」三列，得率着色（≥98%绿 / ≥90%橙 / 否则红）

#### 4.4.4 全链路溯源

- 链路：成品 → 生产订单 → 配方版本 → 完整配方树（递归展开子配方）→ 实际出库批次 → 采购入库单（关联供应商/厂家）
- 溯源弹窗展示配方谱系树与实际领料批次追溯表（物料、批次号、用量、来源单据）

### 4.5 采购管理

- **原料采购**：仅关联材料供应商；一个采购合同允许多个物料明细（v5.0 起新建为单据式：同一合同号多物料批量创建，`POST /raw-material-purchase/batch`）；审核/反审核机制
  - **物料分类限制（v4.5）**：物料下拉仅显示大类 A/P/F/R/S（助剂/颜料/填料/树脂/溶剂），不含半成品(B)和成品(C)
- **成品采购**：仅关联成品供应商；品名选择限定成品物料（category=C），自动带出编码与品牌；物料下拉每项显示「成品」绿色标签；v5.0 起新建同样为单据式多物料（`POST /finished-product-purchase/batch`）
  - **品牌归属校验（v4.5）**：保存时校验供应商名称 = 物料 `brandOwner`，不一致报错「供应商与物料品牌归属不一致」；前端选择物料后自动过滤供应商下拉仅显示匹配 brandOwner 的供应商
- **采购到货**：到货后创建来料质检单，质检合格才触发入库（见 4.8）

### 4.6 库存中心

#### 4.6.1 库存管理（只读）

- **只读展示**，不提供出库/调整操作入口
- **双视图（v5.22）**：顶部「按编码 / 按批次」切换
  - **按编码**：同一编码跨批次/库位**合计总量**——编码、品名、单位、批次数量、库存总量、可用总量、均价（金额÷数量）、总价、最新入库日期
  - **按批次**：同一编码同一批次跨库位**合计余量**——编码、品名、批号、库存量、可用量、单价、总价、库龄、入库日期（最早）、过期日期（最晚）、剩余天数、质检状态/单号/检测结果/检验员/检验日期（按「物料+批次」精确匹配）
- 顶部仓库切换（选中绿色高亮）、编码/品名（批次视图含批号）模糊搜索、分页（50/100/200）
- **点击均价/单价弹出价格走势折线图（v5.20）**：数据源 = **采购单价格（带供应商） + 台账入库价格** 合并（按日期+价格去重、日期升序、标注来源），任何有入库记录的物料均有走势；弹窗宽 900px，X 轴完整显示日期，悬浮提示防裁剪
- **可用量异常提示（v4.3）**：当「可用量」与「库存量」不一致时，可用量数字红色高亮，用于识别历史脏数据（系统未启用占用功能，正常情况下两者应相等）
- **导出 Excel（v5.23）**：页面右上「导出 Excel」按钮，导出当前视图与筛选条件下的全量数据（xlsx）；双视图导出列与页面一致；价格/成本列无权限限制（与页面直出一致，成本保密原则针对出库选批号场景）

#### 4.6.2 其他出库 / 其他入库

- 其他出库：原因 SCRAP(报废)/SAMPLE(样品)/LOSS(盘亏)/RETURN(退货)/OTHER；**批号强制必选**，成本按批号直取
- 其他入库：支持三级库位选择与单价录入
- **业财一体化可选生成 AR/AP（v4.2）**：其他入库/出库单据新增财务字段，由单据勾选决定是否生成应付/应收
  - 字段：genFinance(是否生成)、financeAmount(金额)、financePartnerId(客商ID)、financePartnerName(客商名称)、financeDocNo(已生成单号，冗余追溯)
  - 其他入库勾选「生成应付」→ 质检合格入库后自动生成 AP（payableType=OTHER）
  - 其他出库勾选「生成应收」→ 创建即自动生成 AR
  - 未勾选则仅为库存调整，不涉及财务
- **采购退货全流程（v4.1，v5.4 移至采购管理并改名「采购退货单」，v5.5 修正流程）**：质检判定不合格的货物**从未入库**（REJECT 不触发入库），退给供应商不走仓库
  - **触发**：QC 来料质检（INCOMING+PURCHASE）判定"退货"(REJECT) 时，自动生成采购退货单(DRAFT)；该批货物不触发入库、**不生成应付**（收货才立应付）
  - **审核**：采购员在「采购退货单」页审核通过 或 驳回（权限 `purchase:read/write`，v5.4 由原 `inventory:*` 迁移）
  - **完成（v5.5）**：审核通过即退货完成(DONE)——货物直接退回供应商（无出库操作、无库存变动），**无财务动作**：不生成应付、也不冲减应付（退货部分从未立账，冲减会误伤同单其他合格物料的应付）
  - 幂等：同一质检单仅生成一张退货单；DONE 后不可重复审核
  - 退货单状态流转：DRAFT(待审核) → DONE(已退货完成)；或 DRAFT → REJECTED(已驳回)
  - **已退货明细 Tab（v5.4）**：页面双 Tab——「退货单处理」（含状态筛选与操作）/「已退货明细」（status=DONE 记录，独立分页，含审核人/退货完成时间）
- **销售退货全流程（v5.4）**：客户退货，走「销售退货」驱动入库（菜单：销售管理 → 销售退货，权限 `sales:read/write`）
  - **创建**：销售员手工创建退货单(DRAFT)，可「参照销售出库单」一键带出客户/物料/单价（`GET /api/outbound/sales`），或手工选择客户+物料录入；单号 `SR-YYYY-NNNN`（与采购退货 `RO-` 区分）
  - **审核**：销售员审核通过(APPROVED) 或驳回(REJECTED)（复用通用审核逻辑）
  - **入库**：仓管参照已审核退货单做退货入库（`POST /api/sales-return/{id}/inbound`），选择仓库/分库/库位，**自动生成新批号**增加库存，生成 OtherInbound 单据(reason=RETURN，复用预留退货关联列：return_ref_type/return_ref_id/return_ref_doc_no/customer_id/return_amount/return_offset_status=APPLIED)
  - **冲减应收**：入库确认时自动按原销售订单号 FIFO 红冲未结清应收账款（receivedAmount 累计），并回写 `sales_order_item.return_qty`
  - 幂等：同一退货单仅生成一张入库单（other_inbound.return_ref_id 防重）
  - 退货单状态流转：DRAFT(待审核) → APPROVED(已审核待入库) → DONE(已入库完成)；或 DRAFT → REJECTED(已驳回)
  - **已退货明细 Tab（v5.4）**：双 Tab 展示，明细含客户/原销售单号/入库单号/审核人/入库时间

#### 4.6.3 盘库管理

- 三种操作（StockCheck 实体，docType 区分）：
  - 盘盈：实盘 > 系统，增加库存，记录 ADJUSTMENT 异动
  - 盘亏：实盘 < 系统，扣减库存（校验充足）
  - 库位调整：同仓库内库位间转移，总量不变

### 4.7 销售管理（v4.0 完整闭环）

#### 4.7.1 销售订单

- 创建：选客户、合同号、发货仓库、期望发货日期 + 明细行（物料/数量/单位/单价，金额自动汇总）
- 状态流：**DRAFT → CONFIRMED → SHIPPED**（无明细不可确认；仅草稿可删除）
- 支持分批发货，明细跟踪已发数量；全部发完自动置 SHIPPED

#### 4.7.2 发货出库（参照订单）

- `POST /api/outbound/sales/from-order`：批号强制必选（下拉显示分库/库位/现存量，不显示价格），发货数量可编辑（不超过未发量）
- **发货仅生成草稿单据（DRAFT）**：不扣库存、不生成应收，由仓管在销售出库列表审核确认后统一处理
- **仓管审核确认**：扣减库存 → 出库单按批号记录实际成本 → 回写销售订单明细已发量 → 生成应收账款 → 全部发完自动置 SHIPPED
- **销售出库不再做质检校验（v4.3）**：入库时已确保质检合格，库存即合格，出库无需重复校验
- **发货自动生成应收账款**（金额=发货量×销售单价，关联订单号/合同号）
- **应收到期日按客户收款条件自动计算（v4.5 更新）**：款到发货=当天；账期N天=发货日+N天；**月结=次月1号；两月结=+2月1号；三月结=+3月1号**；客户未设置则回退期望发货日

### 4.8 质检管理

**统一为来料质检模型（v4.2）**：取消「出厂质检」概念。所有入库（采购/生产/委外/其他）均需经来料质检合格方可入库，确保库存物料均为合格品。出厂产品（含销售出库）均为已质检合格的成品。

1. **来料质检统一模型**：
   - 采购到货审核 → 生成待检质检单（refDocType=PURCHASE）
   - 生产入库确认 → 生成待检质检单（refDocType=PRODUCTION_INBOUND）
   - 委外入库确认 → 生成待检质检单（refDocType=OUTSOURCE_INBOUND）
   - 其他入库创建 → 生成待检质检单（refDocType=OTHER_INBOUND）
2. **质检判定（v4.5 改名，原 QC 判定）**：合格 PASS / 让步接收 CONCESSION / 退货 REJECT
   - 合格/让步 → 触发入库（回写单据状态为 DONE）+ 生成应付（委外加工费/其他入库勾选时）
   - 退货 → 采购入库自动生成退货单（v4.1）；回写单据状态为 REJECTED
3. **销售出库门禁**：批号必须已通过质检（PASS/CONCESSION），否则禁止出库（v4.3 起销售出库不再校验，库存即合格）
4. **质检模块界面（v5.0 分类 Tab）**：按被检物料类型分「材料质检（A/P/F/R/S）/ 半成品质检（B）/ 成品质检（C）」三个 Tab，每个 Tab 内含「待质检」（status=PENDING）与「已质检」（多条件搜索+分页）子页，Tab 标签带待检数量徽标
5. **质检单打印（v5.24）**：「已质检」列表操作列「打印」按钮（仅已判定单可打印）→ 新窗口 A4 正式质检报告（COA）：公司抬头 + 报告编号 + 物料/批次信息 + 检验项目空白表（留白手填）+ 判定结论勾选 + 签字栏；HTML 生成函数 `buildQcPrintHtml(row)` 为纯函数（无后端依赖，行数据即全字段）

### 4.9 财务管理

**业财一体化原则（v4.2）**：所有物料进出均与财务挂钩。对外交易自动生成 AR/AP，内部成本流转（生产领料/生产入库）不产生 AR/AP。

#### 4.9.1 应收账款（AR）生成时机

| 来源 | 生成时机 | 金额 |
|---|---|---|
| 销售出库 | 发货确认时自动生成 | 发货量 × 销售单价 |
| 其他出库 | 单据勾选「生成应收」时，创建即生成 | financeAmount |

- 应收到期日按客户收款条件自动计算（见 5.4）
- 状态：UNPAID(未收款) → PARTIAL(部分收款) → PAID(已结清)

#### 4.9.2 应付账款（AP）生成时机

| 来源 | 生成时机 | 金额 |
|---|---|---|
| 采购到货 | 到货审核时自动生成（货到即负债） | 采购订单 totalAmount |
| 委外入库 | 质检合格时自动生成加工费 AP | 入库数量 × 委外订单 processingFee |
| 其他入库 | 单据勾选「生成应付」时，质检合格入库后生成 | financeAmount |

- 同一采购/委外订单仅生成一次 AP（幂等，按订单号查重）
- 赠送采购（isFree=true）不生成 AP
- 委外订单需设置 supplierId(代工厂供应商) 和 processingFee(加工费单价)，否则不生成加工费 AP
- 状态：UNPAID(未付款) → PARTIAL(部分付款) → PAID(已结清)
- payableType：PURCHASE(采购) / OUTSOURCE(委外加工) / OTHER(其他入库)

#### 4.9.3 收款单（PaymentReceipt）

- 记录每一笔收款流水，关联冲减应收账款（AR）
- 字段：docNo(PR-YYYY-NNNN)、arId、arDocNo、customerId、customerName、amount、method(收款方式)、bankAccount、receiptDate、operator、remark
- 收款方式：BANK(银行) / CASH(现金) / ACCEPTANCE(承兑汇票)
- 创建收款单时自动回写 AR 的 receivedAmount，状态自动流转
- 一个 AR 可分多次收款（多张收款单）

#### 4.9.4 付款单（PaymentDisbursement）

- 记录每一笔付款流水，关联冲减应付账款（AP）
- 字段：docNo(PD-YYYY-NNNN)、apId、apDocNo、supplierId、supplierName、amount、method、bankAccount、payDate、operator、remark
- 付款方式：BANK(银行) / CASH(现金) / ACCEPTANCE(承兑汇票)
- 创建付款单时自动回写 AP 的 paidAmount，状态自动流转
- 一个 AP 可分多次付款（多张付款单）

#### 4.9.5 历史数据补偿

- 启动时自动扫描已审核到货记录（status=APPROVED），若对应采购订单尚未生成 AP 则补录
- 历史委外入库单状态对齐：CONFIRMED 且无待检质检单的统一转为 DONE(已入库)

#### 4.9.6 发票管理（v5.36）

- 登记：方向 OUTPUT(销项，开给客户)/INPUT(进项，供应商开来)；选往来单位自动带出税号（customer/supplier 档案 taxNo，可改）；不含税金额 + 税率(13/9/6/0%) 自动算税额与价税合计；纸面发票号码、开票日期、关联订单号（销售/采购单号）可选
- 单号：INV-YYYY-NNNN
- **红冲**：对正常单生成一条负数对冲发票（金额全部取反、单据号新 INV、备注记录红冲原因），原单 status=FLUSHED 并 flushDocNo 指向红字单；红字单与已红冲单均不可编辑/删除（防状态悬挂）
- 汇总口径：净额 = 正常单 − 红字单（红字为负数直接 SUM 抵消）；「开票汇总」弹窗按客户对比 开票净额 vs 应收立账 vs 已回款
- 权限：finance:read/write，金额列 finance:amount 脱敏；导出 Excel

#### 4.9.7 费用管理（v5.36）

- 无往来单据的其他收支登记：方向 EXPENSE(支出)/INCOME(其他收入)
- 费用类型走字典：expense_type（运费/包装费/水电费/办公费/差旅费/维修费/检测费/其他支出）、other_income_type（废料回收/租金收入/利息收入/政府补贴/其他收入），启动幂等补录
- 字段：金额、发生日期、支付方式(BANK/CASH/ACCEPTANCE/WECHAT/OTHER)、往来对象（物流公司/房东等文本）、经手人、备注
- 单号：EXP-YYYY-NNNN；月度利润试算的费用/其他收入取数来源（按登记时间归月）

#### 4.9.8 预收/预付款（v5.36）

- 场景：客户先打款后发货（预收）、先付供应商后到货（预付）
- 登记：方向 RECEIVE/PAY、往来单位、金额、方式、日期；单号 ADV-YYYY-NNNN
- **冲抵联动**：预收冲应收（复用 FinanceService.receivePayment，AR receivedAmount/状态流转一致）、预付冲应付（复用 makePayment）；校验往来单位一致、冲抵额不超预存余额；预存单 usedAmount 递增、状态 UNUSED→PARTIAL→USED
- 已冲抵单不可删除（防 AR/AP 余额悬挂）；收款单超冲转预收的部分与本模块暂不打通（对账单期末以 AR 台账为准）
- 导出 Excel

#### 4.9.9 成本核算（v5.36）

- 生产/委外订单成本归集列表（`/cost-accounting`，默认生产，可切委外）：
  - 生产订单实际成本 = 领料成本（该单 CONFIRMED production_outbound Σcost） + 人工费 + 制造费用（production_order.labor_fee/overhead_fee 两列**手工补录**，系统无工资/制费数据源）
  - 委外订单实际成本 = 发料成本（该单 CONFIRMED/SIGNED outsource_material_outbound Σcost） + 加工费（该单 OUTSOURCE 应付立账 Σamount）
  - 单位成本 = 总成本 ÷ 产出量（DONE 入库 Σqty）
  - **理论成本** = 配方版本 BOM 成本（RecipeService.calcVersionCost：库存加权均价+半成品递归）×（订单批量 ÷ 配方批量）；差异% =（实际−理论）÷理论×100，超 +20% 红 / 低于 −20% 橙
- 权限：finance:read，成本列 finance:amount 脱敏；人工制费补录 finance:write

### 4.10 委外管理（配方表模式）

- **委外订单即配方表**：参照已发布配方版本创建（制漆/制浆分组选择），含产品名称、生产批量、原料明细用量；生产批量 ≥100kg
- **委外订单财务字段（v4.2）**：supplierId(代工厂供应商，关联Supplier)、processingFee(加工费单价，元/单位)；用于委外入库质检合格时自动生成加工费 AP
- **委外出库**（发料，v4.5 重构）：参照已确认委外订单按配方明细领料；批号强制必选（显示分库/库位/现存量）；**用量可直接编辑**；**仅选择调出仓**（不再选择调入仓），选择委外订单后自动展示代工厂名称；参照订单时自动确认
  - **参照订单过滤（v4.6）**：参照下拉仅显示可出库的委外订单，已完工订单（COMPLETED 状态、已存在 DONE 入库单、或已存在 CONFIRMED 出库单）直接不显示。接口 `GET /api/outbound/referenceable-outsource-orders?forType=outbound`
  - **库存直接扣减调出仓**（v4.5 变更）：材料发给委外工厂后所有权转移，调出仓库存减少，**不再调拨到委外仓**
  - 出库单持久化 `processorName`（代工厂名称冗余字段）便于展示
  - 发料不单独生成 AP，加工费在入库时按"入库数量×加工费单价"统一结算
- **委外入库**（回库）：参照委外订单，三级库位选择，自动生成批号；同样记录理论产出与得率；页面直出实际材料成本（按发料出库批号成本汇总）与单位成本
  - **参照订单过滤（v4.6）**：参照下拉仅显示可入库的委外订单（必须已出库且无 DONE/CONFIRMED 入库单），已完工订单直接不显示。接口 `GET /api/outbound/referenceable-outsource-orders?forType=inbound`
  - **前置校验（v4.5）**：必须先完成委外出库（领料），未委外出库的订单不允许参照生成委外入库单，系统提示「该委外订单尚未进行委外出库，不允许参照生成委外入库单」
  - **质检合格自动生成加工费 AP**（v4.2）：AP金额 = 入库数量 × 委外订单 processingFee；同一委外订单仅生成一次（幂等）
- **委外订单打印（v5.25）**：「委外加工单」——操作列「打印」（仅已确认/已完工），A4 打印：订单头（单号/产品/配方编号/代工厂/批量/状态/制单人）+ **发料明细只显示物料编码+用量（无品名，配方保密防外泄）** + 发料人/代工厂签收签字栏；不显示加工费（财务不外露）；`GET /outsource-order/{id}` 取数

## 5. 核心业务规则汇总

### 5.1 批号体系

- **入库**：所有入库类型（采购/其他/生产/委外）确认时**强制自动生成批号**（B+日期-当日序号），记录入库日期
- **出库**：所有出库类型（生产/委外/其他/销售）**必须选择批号**，前后端双重校验
- **批次展示**：出库选批号时显示「批号 + 分库/库位 + 现存量」，**不显示价格**（价格保密，成本在后台按批号直取）
- 库存台账按（物料+批号+仓库+库位）精确定位；出库扣减必须携带库位才能命中台账行
- **出库校验基于 qty（v4.3）**：出库/调拨时校验 `qty`（实物库存量）而非 `availableQty`（可用量）。系统未启用占用功能（occupiedQty 始终为0），`availableQty` 为冗余字段，历史脏数据会导致「有库存却无法出库」。错误提示格式：`库存不足: {物料} 批次{批号} 仓{仓库} 库存{qty} 需要{出库量}`
- **过期批次禁出（v5.23）**：出库扣减前校验批次过期日期 `expiryDate < 今天` 即拦截（当天到期当天仍可出库），提示 `批次 X 已于 YYYY-MM-DD 过期，禁止出库（过期物料请走「其他出库-报废」处理）`；**正常业务出库一律拦截**——销售出库、生产领料、委外发料、其他出库（非报废类）；**报废 SCRAP / 样品 SAMPLE / 退货 RETURN 放行**（过期料处理通道）；跨仓调拨/委外调拨同样拦截；拦截点在 `InventoryService.outbound`（所有出库汇聚点）与两个调拨方法

### 5.2 成本体系

- **配方成本**：库存加权均价 + 采购价回退，半成品递归子配方（取价规则见 4.3.3）
- **出库实际成本**：出库单落库 unit_price（批号库存单价）与 cost（qty×unitPrice），按批号直取
- **半成品/成品实际材料成本**：按订单汇总已确认领料出库的 cost（`/api/outbound/production/actual-costs`、`/outbound/outsource/actual-costs`），在生产入库/委外入库页面直出
- **订单成本核算（v5.36）**：材料 + 委外加工费 + 人工制费（手工补录）= 订单总成本；与配方理论成本按订单批量折算对比，差异%超±20%预警（见 4.9.9）
- **保密原则**：操作员可见界面不展示单价/成本（批次下拉、配方打印），成本仅在成本核算与报表场景呈现

### 5.3 得率体系（v4.0）

- 生产入库/委外入库记录：实际产出 qty、理论产出 theoreticalQty（订单配方批量）、得率 yieldRate = 实际÷理论×100
- 生产报表输出批次得率趋势与按产品损耗分析（仅统计 CONFIRMED 单据）

### 5.4 账期与收付款（v4.0 + v4.2）

- 客户收款条件（账期缓冲）+ 收款方式（电汇/承兑），供应商付款条件 + 付款方式，共用同一套字典
- 应收到期日按客户账期自动计算（规则见 4.7.2）
- **收付款单（v4.2）**：收款单/付款单记录每笔收付款流水，支持银行/现金/承兑三种方式，创建时自动冲减关联 AR/AP 的已收/已付金额并流转状态
- **AP 默认账期**：采购到货/委外入库/其他入库生成的 AP，到期日默认为生成日 +30 天

### 5.5 单据驱动原则

- 所有库存变动必须由单据驱动：单据 DRAFT → 确认触发库存异动（InventoryMovement 全程留痕）
- 参照订单场景（生产领料/委外发料/销售发货）自动确认；其余手动确认
- 出库单据四类实体：ProductionOutbound / OutsourceMaterialOutbound / OtherOutbound / SalesOutbound

### 5.6 采购退货财务处理（v4.1，v5.5 修正）

- **流程**：QC 来料质检判定退货 → 自动生成退货单(DRAFT) → 采购员审核 → **审核通过即退货完成(DONE)**
- **财务规则（v5.5）**：**收货才立应付**——退货物料从未入库、从未生成应付，退货单**不生成应付、也不冲减应付**（冲减会把同单其他合格物料的应付冲少）；退货单仅记录退货事实，金额列（退货数量×原采购单价）仅作展示与统计
- **库存影响**：无——REJECT 货物不触发入库，从未进入库存台账，退货不产生任何库存变动

### 5.7 业财一体化规则（v4.2）

- **对外交易自动生成 AR/AP**：采购入库→AP、委外入库→AP(加工费)、销售出库→AR
- **其他出入库按勾选生成**：单据 genFinance=true 时生成，否则仅为库存调整
- **内部成本流转不产生 AR/AP**：生产领料出库、生产入库为内部成本归集，不涉及外部客商
- **委外发料不单独生成 AP**：加工费在委外入库时按"入库数量×加工费单价"统一结算
- **幂等性**：同一采购/委外订单仅生成一次 AP（按订单号查重）
- **状态回写**：质检合格/退货时自动回写入库单据状态（DONE/REJECTED）

### 5.8 物料编码规则（v5.40-43 定稿）

- 6 位 = 小类码(2字母) + 序号(4数字)，小类码首位恒为物料大类字母（A/P/F/R/S/B/C）
- **数字 0001-9999 全局连续、每个数字只使用一次**（AC0001 之后无论何类都是 0002）——工人只看数字也不会拿错料
- 编码在保存成功时才取号（填单放弃不占号）；删除无引用物料数字回收入池（released_code_seq）优先复用；被 23 张单据表引用或有台账即禁删
- 禁用物料：选料下拉不可见 + 采购/销售创建后端硬校验拒绝
- **v5.65 半成品/成品新编码体系（参照大厂涂料产品编码，历史不动仅新增生效）**：半成品 7 位=色浆小类+主材+分组流水（BWF0001=白浆/氟碳系）；成品 8 位=漆型+主材+色系+分组流水（CWZH0001=面漆/聚酯/白），看码即知属性、与原料 6 位全局连续体系彻底分开（成品每天新增不再消耗原料序号池）；易混字符约束：新码字母段禁 I/L/O（蓝浆 BL→BU），流水数字 0/1 正常

### 5.9 仓库隔离分库体系（v5.38-39）

- 每个一级仓（芃远自有/邦弗特山东/昇润广东）必备 5 个隔离分库：原材料/半成品/成品不合格品库（UNQUALIFIED_RAW/SEMI/FIN）+ 聚酯/氟碳油尾库（TAILING/TAILING_FC）
- 隔离判断锚点=库位→分库 zone_type；入库防线（隔离库位仅质检不合格/油尾退回通道）、出库拦截（隔离区仅报废通道、油尾区放行生产领料）、FIFO 同口径
- **过期闭环**：过期批次按物料大类自动搬入对应不合格品库 + 自动生成复检评估单（PENDING）→ 判定合格填新有效期→移回普通库位恢复；不合格维持隔离走报废

### 5.10 物料操作铁律（v5.46）

- **无论什么操作，物料必须精确到批号、仓库必须精确到库位**：台账入口双非空硬校验、盘库三入口前置校验、库存流水（inventory_movement.location_id）精确到库位
- 出库口径（用户确认）：批号人工必选，库位系统按 FIFO 自动分配、流水记录实际扣减库位

### 5.11 总账体系（v5.61，推翻此前「总账/凭证不做」的定位）

完整账务闭环：**期初建账 → 凭证（手工 + 业务单据生成）→ 记账 → 账簿（余额表/明细账）→ 结转损益 → 结账 → 三大财务报表**（资产负债表/利润表/现金流量表，小企业会计准则格式，均可打印 + 导出）。
与既有「利润试算」（管理口径）并存、口径互不干扰。

- **科目**：两级结构（如 6602.01 管理费用-办公费），预置 70 个小企业准则常用科目；编码/类别/方向不可改（报表锚点），已引用科目只可停用
- **凭证**：统一「记」字，VCH-YYYY-NNNN 按凭证日期年份编号；DRAFT 草稿 → POSTED 已记账（记账 finance:audit / 反记账 finance:reverse-audit，两码 v5.36 起预置、本版启用）；借贷不平禁止保存；红字凭证允许负数分录
- **业务转凭证**：收款单/付款单/费用单/发票四类单据一键生成分录预览（默认科目按 account_mapping 映射可配置），确认后存草稿；source+refDocNo 查重防重复生成
- **期初建账**：各科目存量余额录入（旧账/代账交接），借贷必须平衡、损益类禁止期初；是三大报表年初数的来源
- **结转损益**：按「年初至该期损益科目 POSTED 余额」生成结转凭证（余额口径天然幂等），生成草稿需人工记账
- **结账**：期间 YYYY-MM 结账前置=无草稿 + 损益已结平；已结账期间禁止一切凭证写操作；反结账仅允许从最近已结期间逐月往前
- **报表口径**：一切余额 = 期初建账 + 年初至该期 POSTED 净发生额（含结转凭证）；利润表排除结转凭证；资产负债表「未分配利润」= 3104+3105+未结转损益（结转前后恒等）；现金流量表为简化直接法（现金科目按对方科目比例分摊归集，现金内部转账不计入）
- **不含**：销售出库成本自动结转（成本核算模块另有口径）、年末利润分配结转（手工录凭证）
- 权限全复用 finance:read/write/audit/reverse-audit/amount，GM/FINANCE 零补权限

### 5.12 工资核算与固定资产（v5.62）

补齐标准 ERP 的「人、物」两块，直接生成凭证喂给总账（v5.61），月末手工凭证进一步减少。

- **员工档案**：独立于登录账号（工人无账号也能建档）；部门（生产/销售/行政/技术/质检/其他）决定工资计提的费用科目
- **工资单**：按月一张（同期间唯一），新建自动带出在职员工（基本工资预填）；构成 = 基本 + 奖金 + 计件（手填）− 扣款 = 应发，再减代扣社保/个税（会计手填，系统不做累计预扣）= 实发；草稿→确认锁定
- **工资凭证一键生成**：计提（借按部门归集：生产成本-直接人工/销售费用/管理费用，贷应付工资）+ 发放（借应付工资，贷银行存款+其他应付款-社保+应交个税），source+单号防重复
- **固定资产**：卡片（类别/原值/年限/残值率/折旧科目按卡配置，默认管理费用-折旧费、生产设备可选制造费用）；平均年限法，购入次月起提、报废当月照提、提满提尾差
- **月度折旧一键计提**：逐卡生成折旧记录 + 按折旧科目汇总生成凭证（借费用科目，贷累计折旧）；已结账期间拦截
- 权限复用 finance 系（GM/FINANCE 零补）；操作日志自动归类（工资核算/员工档案/固定资产）

### 5.13 存货计价方式可配置（v5.63）

四档可选：个别计价（默认，=既有口径）、先进先出（引导选最早批次）、移动加权平均、全月平均（月中暂估+月末一键回填）。按准则「一经确定不得随意变更」：变更必填原因、留痕、只影响未来出库、建议年初切换；全月平均模式下期末结账前置「存货成本计算」。同步修正口径：生产/委外成品入库按订单归集成本写入批次台账价（此前为 0，销售毛利虚高），利润试算自此出现真实毛利。

### 5.14 生产领料差异三通道（v5.64）

工人实际投料与领料单有出入的处理闭环：**多领 → 生产退料**（按订单已领明细部分退，负数行自动冲减订单成本、库存按原批次原库位加回）；**少领/追加 → 补领**（已领料订单追加领料，仅填追加用量行）；**整单开错 → 领料单作废**（原行与冲减行同置 CANCELLED，订单成本清零、投出比自动剔除，不可逆；订单已入库或已部分退料时拦截）。铁律：单据确认后不可改，差异一律走反向单据冲正。

## 9. 部署运维

1. 前端构建：`cd pims-web && npm run build`（产物输出到后端 static 目录）
2. 后端打包：`cd pims-server && mvn clean package -DskipTests`
3. 启动：`java -jar target/pims-server-1.0.0.jar`（端口 8080，前端 SPA 同端口托管）
4. 数据库备份：直接复制 `data/pims.db`（WAL 模式建议停服复制）
5. 升级：替换 jar 重启即可；表结构差异由启动初始化器幂等补齐，无需手工 DDL
6. **机房服务器部署（v4.9）**：详见 `docs/DEPLOY.md`——64G 内存利用策略（JVM 堆 4G + OS 页缓存为主，勿盲目加大堆）、Windows `start.bat` / Linux systemd 部署、企业域名 + Caddy/nginx 反代 HTTPS 外网访问、安全基线

**默认账号**：admin / admin123（角色 SS，全权限）
